# FxEmbed 数据源

2026-09-09 接入，无新增依赖，保留项目 MIT 协议。调用第三方公开服务，不复制服务端代码，也不需要 X Token、Cookie 或开发者账户。

## 接口与实现

- [用户资料](https://docs.fxembed.com/api/twitter/operations/2profilehandle/)：`GET https://api.fxtwitter.com/2/profile/{handle}`，验证返回用户名并缓存数字用户 ID。
- [用户时间线](https://docs.fxembed.com/api/twitter/operations/2profilehandlestatuses/)：`GET https://api.fxtwitter.com/2/profile/id:{userId}/statuses?count=100&with_replies=1`。排除回复时不发送 `with_replies`，同时在本地再次过滤。
- 使用 `cursor.bottom` 分页，不请求分组线程、翻译或 RSS，不使用单页 `since` 优化。
- 验证 HTTP 状态和响应内 `code`；拒绝显式 `stale=true`、部分错误、不完整结构、缺失目标帖发布时间。意外的 204 也作为失败，因为本适配器没有请求 `since`。
- 只保留 `author.id` 等于已解析用户 ID 的顶层帖子，排除 `reposted_by`。不依据 URL 或显示名称判断作者，不拼接引用正文。
- 原文优先取 `raw_text.text`，缺失时取 `text`；标准化发布时间为 UTC ISO，再交给已有事件时间解析器。媒体使用 `media.all`。
- 第一次取一页建立基线；后续取到整页 ID 均不晚于检查点或没有下一页为止。返回数量不视为分页完成依据；页内旧帖、置顶或其他作者不单独触发停止。重复游标、100 页上限、20 秒请求超时均导致整批失败。
- 不自动降级到官方 X API。`SOURCE_PROVIDER=x` 是唯一启用官方数据源的配置值。

## 运维与边界

默认五分钟轮询。请求失败不在同一轮高频重试，下一轮再尝试。监控会保留旧检查点和待发队列，并以非零退出码报告本轮失败；已入队通知仍可继续投递。首次成功、没有新增帖和抓取失败在运行状态中分开记录。

第三方时间线并非有完整性证明的事件日志。停止规则假设大体按时间倒序；无标记的旧缓存、上游遗漏、严重乱序、编辑或删除无法全面检测。接口可用也不代表完整。不能因为接口返回旧帖子就断定故障：账号也可能确实未发新帖。没有可承诺的实时 SLA，短期实测不能替代持续监测。

数字帖子 ID 可与官方源共用；切换不清空 outbox，不重新初始化已有检查点。默认不补发检查点之前的历史。状态文件不增加任何第三方凭证。

## 验证

模拟测试覆盖作者混入、纯转帖、回复选项、长文和媒体、旧上下文、跨页重复、空页、内外层错误、HTML、超时类传输失败和分页中途失败。监控集成测试验证失败不推进检查点、已有待发通知继续发送及恢复后去重。
